# Design brief

Complete from user confirmation or repository evidence before implementation. Link each source; mark unknowns instead of filling them with assumptions.

```md
## Goal
- User and task:
- Success condition:
- Source:

## Constraints
- Supported platforms and viewports:
- Content and interaction states:
- Accessibility expectations:
- Existing components, tokens, and conventions:
- Sources:

## Change
- Information hierarchy and primary action:
- States to implement or preserve:
- Out of scope:

## Execution
- Frontend check command:
- Browser or screenshot command/path:
- Representative routes, fixtures, or accounts:
```

Brief example form: “Source: `docs/product.md` describes the signed-in settings task; `src/ui/` provides the component convention; browser command is recorded in `package.json`.” This is an evidence pattern, not a fact about every project.
