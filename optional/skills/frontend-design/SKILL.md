# Frontend Design

Use this optional workflow only when interface quality needs a repeatable project procedure. It is disabled by default and does not promise better outcomes without paired trials.

Before changing UI, obtain the project’s users, task, content states, supported viewports, design standards, component conventions, accessibility expectations, and frontend commands from the user or repository evidence. If a needed fact is absent, state it as unknown; do not invent branding, a visual style, service behavior, or a verification command.

Write the design brief in `references/design-brief.md`. Implement within the established system, keeping interaction states and semantics tied to the brief. Use the project’s supplied browser or screenshot path to exercise the documented flows and viewport/content cases. Record the evidence using `references/verification-contract.md` and report unverified behavior.

Do not use this workflow for a wording-only edit, backend task, or generic design advice.
